# Maneko 产品化与应用商店发布准备设计

日期：2026-10-08

## 目标

把现有 Maneko Web + FastAPI + Capacitor Android 产品整理到核心功能真实可用、可重复构建、可部署、可供商店审核的发布候选状态，并明确仍依赖运营者账号或法律/平台审核的事项。目标不是声称应用已经获商店批准。

## 当前边界

- 保留 React/Vite、FastAPI、Capacitor Android 和现有服务接口。
- 核心功能完整性是发布硬门槛：真实上传/粘贴小说、服务端持久化、分章与阅读、书库导入与管理、选择风格、真实后端异步生成分镜与图片、任务进度/失败恢复、漫画查看与导出，在 Web 与 Android 发布入口中都必须能完成。
- Android 商店版本不得默认进入样例数据/离线演示模式，也不得把不可用的后端能力伪装为成功；无生产 API 配置时应在构建前失败或明确阻止发布构建。开发者仍可保留显式的本地预览模式，但预览数据必须与真实用户数据和发布版本隔离。
- 本轮还聚焦生产配置、可诊断性、用户数据/隐私披露、Android release 构建及上架材料。
- 不增加登录、云同步、支付、订阅或新的服务端存储供应商。
- 不在仓库写入生产密钥、签名密钥或真实用户数据。
- 保留开始任务前已经存在的工作区改动；最终只提交本轮明确纳入的文件。

## 核心功能完整性验收

- Web 与 Android 发布构建均连接配置的真实 API，不以本地演示数据替代书库、章节或生成结果。
- 小说上传/粘贴可完成解析并展示章节；失败时保留用户可恢复的输入并展示明确原因。
- 真实生成链路可创建任务、显示状态、处理成功/失败/重试或恢复，且生成图片可浏览和导出；生产配置缺少模型凭据或选用 mock provider 时，发布预检必须阻止发布或给出明确阻断错误。
- 书库的线上来源、搜索、导入、收藏/分类/阅读进度等现有核心能力逐项核对；不能把仅元数据的版权书源呈现为可读取全文。
- 用端到端验收覆盖上传 → 分章 → 生成 → 查看结果，并覆盖 Android/Web 前端的真实 API 连接；不能仅以 lint/build 或 mock 单测宣称功能完整。
- 逐项检查应用入口中的“演示模式”、占位书籍和演示分镜：发布版本默认关闭并隔离；如明确保留演示入口，必须标记为预览且不冒充正式功能。

## 方案

### 后端运行可靠性

配置继续从后端工作目录的 `.env` 读取。启动时验证数据库连接和必要目录；提供存活与就绪检查，便于 Render 和本地诊断。生产 CORS 示例使用明确域名，移除误导性的通配符写法。部署说明区分临时磁盘和持久磁盘，并警示 SQLite/本地文件对多实例扩展的限制。上传限制和错误响应需与现有链路兼容。

### 核心产品链路与数据透明

先对照前述核心功能验收走查 Web、移动 Web 和 Android 的真实 API 工作流，修复缺失、断开的或被演示模式替代的功能；网络错误、后端不可用、上传限制和生成失败均须可理解、可恢复，不能静默成功。提供面向用户的隐私说明页面，准确披露小说文本、生成提示和图片可能发送给配置的 AI 服务，以及本地部署时数据保存在部署者配置的数据库/磁盘。说明删除/保留方式、第三方服务和未成年人/版权责任，不承诺未实现的自动删除或加密。

### 视觉主题

将当前高亮霓虹视觉调整为适合长时间阅读与内容创作的低刺激主题：降低粉色/青色等强调色的饱和度和发光面积，以温和的纸感/墨色或中性深色作为阅读底色；仅在关键操作、选中状态和少量品牌细节使用受控强调色。建立语义化颜色 token，统一桌面 Web、移动 Web 和 Android WebView 的背景、文本、卡片、边框、按钮、状态色与焦点样式。检查所有页面状态的对比度、键盘焦点、窄屏布局和减少动态效果偏好；保留日漫品牌识别，但不让装饰抢过小说正文和漫画图像。

### Android 发布

为 Android 设置稳定的包标识、版本号策略、应用标签及商店图标资源；构建脚本支持调试包与签名 AAB，签名材料只从环境变量/本地未跟踪属性读取。构建前检查生产 API 地址、版本和签名配置；提供可复现的构建步骤。不得把调试签名或 API 密钥放入仓库。

### 发布材料与门槛

补充商店发布清单：隐私政策托管 URL、数据安全声明、内容分级、截图/描述、应用访问说明、签名与版本升级、目标 API/政策复核、测试轨道验证。区分仓库可完成事项与需要开发者账号、真实生产服务、法务确认或商店审核的事项。

## 验收

- 后端健康/就绪响应区分进程存活与依赖可用，生产检查可诊断数据库。
- 核心功能完整性验收逐项通过；生产构建不默认加载演示书籍、演示漫画或 mock 图片服务。
- 真实 API 的端到端链路覆盖上传 → 分章 → 异步漫画生成 → 结果查看；Android 发布入口也验证连接同一生产 API 的完整使用路径。
- 前端 lint/build 通过；后端自动化测试可运行，外部模型用例明确隔离或标识。
- Android 调试构建可复现；release AAB 在配置签名参数后可构建，缺参数时给出清晰错误。
- 隐私和商店材料准确描述现有行为，不虚构产品能力。
- 两套前端的关键页面使用统一低饱和语义 token；正文、次要文字、控件边界与焦点满足 WCAG AA 对比要求，移动视口无横向溢出。
- README/发布指南与实际端口、目录、脚本和配置一致。
- 推送前检查差异与目标分支；不覆盖已有用户改动，不提交密钥/数据库/生成内容。

## 外部发布依赖

Google Play 或其他应用商店的最终发布还需要运营者提供开发者账号、公开隐私政策 URL、真实后端域名与持久化策略、生产 AI 服务凭据、签名密钥备份，以及对适用地区法律和商店政策的确认。若真实 AI 服务凭据、生产 API 或持久存储未配置，不能把发布候选称为功能完整。代码工作无法代替商店审核或法律意见。
